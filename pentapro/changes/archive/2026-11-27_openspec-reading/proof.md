**Differential harness requirement:** a reproducible repository test/fixture runner accepts an explicitly supplied already-built pinned upstream executable; it must not automatically download/install dependencies or use user HOME. Require exact SHA verification and record Node version/build identity; build and run reference in isolated directories with `DO_NOT_TRACK=1`, `OPENSPEC_TELEMETRY=0`, `OPENSPEC_NO_UPDATE_CHECK=1`, `NO_COLOR=1`, `CI=1`, `TERM=dumb`, isolated HOME/XDG. Run both binaries in separate equivalent temp roots. Check full stdout/stderr/exit: JSON compare object fields/types/array ordering and missing keys, retaining stdout/stderr channel and exit; human compare exact bytes. Normalize only test root absolute path to `<PROJECT>`; do not normalize diagnostics, order, whitespace in human output, or status. Pin UTF-8 byte fixtures, symlink setup, env and actual binary identities; retain MIT notices when adapted. No executing untrusted record text.

Coverage: empty and nested specs, root absence, config override refusal (including benign global config/data directories, config.yml, malformed YAML and pointer), nearest and implicit no-root text/JSON distinctions, missing ID, path traversal, internal/external/dangling/file/directory links, invalid bytes, BOM/CRLF/fenced headings, Purpose/Requirements missing, empty scenarios and heading hierarchy, malformed/unknown flags, no-specs, unreadable paths where permissions can be reliably simulated, and native regression checks. ASCII mixed case, punctuation, digits, non-ASCII and multiple mixed-depth IDs must be refused before success. Differential fixtures exercise safe simple lowercase prefix pairs and the single nested-ID case, plus an unsupported mixed-depth set. Upstream order observations establish neither portable ICU equivalence nor locale independence. Verify no modifications to synthetic project, throwaway HOME/config and native baseline; snapshot excludes transient writes and outside roots, so complement it with source review. Noninteractive input with closed stdin must terminate; terminal output is plain, readable and never prompts. Root selection beyond nearest and unsupported OS errors must have negative tests; the complete pinned Markdown parser is required.

Passing I2 requires executable pinned upstream differential evidence, meaningful independent expected controls, full Rust fmt/clippy/locked tests, collection metadata/links/cases checks and independent spec, code and verification reviews. In CI, no network or upstream checkout is assumed: run committed golden cases by default, with independently reproducible differential suite opt-in against explicit pinned oracle. Distinguish golden replays from executed reference comparisons. Capture tested fingerprint/commands/results. The 33 preliminary probes are [examples](oracle-observations.md) and [boundaries](oracle-boundaries.md); [stable Node rerun](oracle-stable-node.md) matched those results on Linux Node 26.10.0 and added one nonroot EACCES specs-directory case. It did not rerun the separate 14-case readiness/locale matrix, other permission modes, other OSes or Node 24; none proves complete parity. ## Required clarification controls before acceptance

- Root preflight: unset XDG with valid absolute HOME fallback; absolute XDG overriding HOME; set-empty/relative XDG and missing required HOME; stop at selected nearest root; a marker directory `.openspec-store` and marker file `.openspec-store/store.yaml`; mode-000 specs marker metadata EACCES must yield Engine-only `unsupported root selection` exit 2, while upstream produced exit 1 JSON: assert and label intentional divergence. Separately seek an effective successful-preflight/failed-scandir fixture (e.g. execute-only directory), and compare scan diagnostics only when confirmed. Check no mutations and precise refusal precedence.
- Human errors: compare pinned and Engine output on no root, missing typed spec, external link, (plain noninteractive Linux/NO_COLOR); test Engine mode-000 refusal separately and compare post-preflight EACCES only if established; unknown OS errors receive the documented unsupported fallback and never success.
- Parser: run pinned parser/helper fixture matrix including BOM/CRLF, fenced headings, closing hash, nested headings, multiline requirement text, metadata, empty scenario and fallback, plus a missing-Purpose/Requirements file: list reports count zero while JSON show returns `show_error`; raw show returns original text plus LF. No generic unsupported-Markdown bypass.

- Directory-symlink trust boundary (I2-005): create an isolated outside directory with a non-sensitive sentinel `spec.md`; link `<project>/openspec/specs/alpha` to it. In separate equivalent Engine and upstream projects with isolated HOME, compare actual `show alpha --type spec` and JSON stdout/stderr/exit and verify the sentinel is returned; confirm `list --specs` excludes the link. Snapshot both project and external fixture before/after and inspect code for writes. Add a composed-link negative fixture in which the external capability directory’s `spec.md` links back to `<project>/docs/spec.md`: compare pinned and Engine text/JSON stdout, stderr, exit 1 and the diagnostic naming `<project>/openspec/specs/alpha`; verify no writes to either tree. This project-local target is not sufficient to authorize fallback when its file-link parent is outside the specs root. Add controls for a normal internal directory link, a `spec.md` link outside both the capability directory and project, a contained file link with parent within specs root, a dangling file link and a lexical `../` ID. The outside-file exposure is expected compatibility behavior, not a successful security containment test. Restrict all fixture contents to synthetic non-sensitive data.
