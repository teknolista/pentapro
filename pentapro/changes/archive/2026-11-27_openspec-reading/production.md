# PRODUCTION · OpenSpec read compatibility

Runs offline and noninteractively from an existing local project. No account, config creation, managed marker, network, telemetry or model invocation. Runtime does not invoke Node. Native Rust build, install and existing plugin distribution remain as [I1](../../../production/operations.md). Errors use stdout/stderr and exit rules in PRODUCT; users repair their own OpenSpec files or use the upstream tool. Do not change existing files, indexes, credentials, agents, global config or project state.

Differential test infrastructure builds the exact OpenSpec 2.2.0 commit using its frozen dependency lock in an isolated reference checkout; execute tests with network disabled, throwaway HOME/XDG/config and disabled telemetry/update checks. Capture actual Node, pnpm, lock digest, platform, source SHA and CLI binary identity; use stable supported Node where available. The [stable Node evidence](oracle-stable-node.md) reran the 33 initial and boundary cases on Linux Node 26.10.0 and matched Node 27 alpha outputs; neither validates Node 24 or other operating systems. A nonroot Linux EACCES specs-directory case was observed separately. Tests synthesize all fixture files in temporary roots; preserve upstream MIT notice for copied/adapted source/fixtures. No access to user projects. Outside the explicitly supported root and identifier scope, diagnose unsupported safely; on Linux, inspect the effective XDG config/data path or HOME fallback exactly as PRODUCT defines, and refuse rather than creating or modifying it; no silent migration or fallback.

Test subprocess failures/timeouts and unreadable files must be observable. A read-only permission/symlink/path failure never causes partial modifications. Windows, macOS, unsupported locales, power-loss and hostile concurrency require separate evidence and are not certified by Linux checks.
