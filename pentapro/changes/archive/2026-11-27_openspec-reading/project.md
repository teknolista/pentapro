# PROJECT · OpenSpec read compatibility

[Existing architecture](../../../project/architecture.md) and [I1 architecture](../2026-11-26_engine-foundation/project.md) remain authoritative. Add a separate compatibility CLI adapter, read-only root resolver, spec discovery and fenced-aware parser; preserve I1 command behavior and native JSON/error envelope. Upstream OpenSpec uses Node's UTF-8 replacement, localeCompare and path semantics; the selected Rust implementation must match observable contracts, not require Node at runtime. Root store/declared/default selection is outside this increment: apply the conservative exact preflight in PRODUCT, which rejects even benign global OpenSpec config/data directories and nonexact project YAML instead of trying to classify their contents. A design that cannot reliably detect an unsupported override is blocked until expanded root resolution is specified.

The pinned source is behavioral reference; if code/text/fixtures are copied or adapted, retain MIT license and provenance. Pure parsing and path functions should be separately testable while acceptance exercises the actual binary. Read files only: no child process, network, migration, write or global-config mutation in production reader. Enforce the exact lexical-ID and file-link rules in PRODUCT I2-005; a selected capability-directory symlink is treated by pinned OpenSpec as its own trust root, including when its target is outside the project. A final file within that canonical capability root is allowed; the separate project-file-symlink fallback additionally requires the file-link parent to canonicalize within the specs root before the target may canonicalize within the project. An external capability directory whose `spec.md` links back into project/docs therefore fails at the parent check. Follow the pinned `assertDiscoveredSpecFile` and `assertLinkedSpecFileInProject` order and preserve the capability-directory error path. Therefore the adapter can read an external `spec.md` and must not claim physical project-root containment or a sandbox. Restrict exposure through the invoking host’s actual filesystem permissions and trusted-project choices. Discovery does not follow directory links. Static checks do not establish safety against hostile concurrent replacement; do not promise a race-free sandbox. Preserve OS errors and explicitly surface unsupported root/platform/locale semantics rather than output a false success. Later features own full root/store support, broader Unicode/locale fidelity and other command surfaces.

Dependency selection is implementation-owned and must compare mature Rust alternatives against pinned parser semantics, Unicode collation and lockfile/licenses/maintenance; no general parser is presumed equivalent. Prefer a well-tested bounded implementation; verify inputs with pinned tests and actual oracle. Linux is current validation target; Windows/macOS remain unverified. The entire pinned parseSpec helper path is required; a partial lexical detector is not a substitute. If no approach provides exact tested behavior, document the divergence and return to specification review before coding.
