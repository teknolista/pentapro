# PROJECT — ownership and design

- DEC-SDD-1: reuse 24 existing skill owners. penta-pro owns specification content and reconciliation; software-factory owns lifecycle and handoffs; software-delivery owns tasks/implementation; specialist review/testing/security and Git delivery retain their boundaries. Avoid a parallel alias catalog or schema engine.
- DEC-SDD-2: the host main session is the principal exploration/orchestration agent. Existing six specialists and all six host adapters retain configured models/effort. No new model tier is invented.
- DEC-SDD-3: use six fixed change files, with stable requirement/scenario identities and explicit before/after add/modify/remove/rename intent. Unaffected dimensions remain explicit with baseline links.
- DEC-SDD-4: keep actual effects, lifecycle, disposition, user acceptance and publication as separate facts. Safely resume from files/evidence rather than conversational memory.
- DEC-SDD-5: existing initializer and run-record helper remain optional local conveniences. Agent workflows can use ordinary file tools and an approved equivalent execution record; no replacement SDD utility is introduced.
- DEC-SDD-6: retire command-dependent active fixtures in favor of native six-file fixtures and independent positive/negative graders. Preserve sandbox isolation and historical results; do not claim authored scenarios are executed agent trials.

Alternatives considered: keeping two competing change systems, importing a second skill for every operation, or creating a command/schema engine. They add duplicate ownership or contradict the requested fixed agent-guided process.

Risks: instructions cannot enforce honesty or all host permissions; native model behavior needs bounded trials and independent review; archive/consolidation can be interrupted or overlap. Mitigate with explicit snapshots, serial writes, preservation checks, bounded retries and honest unavailable evidence.
