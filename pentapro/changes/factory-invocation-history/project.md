# PROJECT — design

Extend software-factory, the existing execution-record owner, with a package-local standard-library Python helper and a separate versioned event envelope. Keep run.json schema version 1 unchanged. Use its established root/path checks and per-run locking where suitable. Events are append-only JSON Lines with unique event IDs and invocation IDs; summaries are derived rather than a second authoritative database. Append at delegation/result boundaries, never every tool call. Record evidence references and observed metadata, with explicit unknowns. Reject inconsistent retries, invalid event ordering and damaged trailing records without truncation. Do not claim complete host capture from agent compliance alone.

The initial helper may read the current run's event history for validation and summary; it must not enumerate other executions. Retention/sharding is deferred until measured need. Support actual installed package paths and standalone use without checkout-level imports. Failure after an external effect requires observation/reconciliation before retry, not blind repetition. Repository changes require existing structural gates plus behavior tests.

Root orchestrator owns workflow/template/docs/version integration. A factory implementer owns only the event helper and its regression tests. Read-only specialists independently assess fixed snapshots. Existing setup work remains in scope for integrated delivery; unrelated staged documentation is excluded and preserved.

## Event contract version 1

Commands: append --project ROOT --run-id ID --input EVENT.json; summary --project ROOT --run-id ID. The helper never creates a run implicitly.

Every event requires schema_version=1, event_id, invocation_id, run_id, event_type and occurred_at (timezone-aware ISO 8601). dispatch_requested also requires role, task_id, attempt (positive integer), reason, expected_outcome and input_snapshot (source fingerprint). dispatched requires an observed concrete agent_id. Terminal events require a concise outcome; evidence is a list of sanitized locators. Optional fields distinguish model_requested/effort_requested from model_observed/effort_observed, output_snapshot, parent_invocation_id and usage (input_tokens/output_tokens/cost_usd; unknown values are null, numbers must be finite and nonnegative). Enforce identity, recognized fields, ordering and nondecreasing timestamps within each invocation; cross-invocation append order need not be chronological. No inferred actual model/usage or fabricated completion.

Lifecycle: dispatch_requested -> dispatched OR dispatch_failed OR cancelled; dispatched -> completed OR failed OR cancelled OR interrupted; completed -> result_accepted OR result_rejected. Result acceptance here means orchestrator acceptance of an agent return, never developer acceptance or a passed product gate. Other terminal states end that invocation. A true retry gets a fresh invocation_id and incremented attempt for the same task. Resubmitting the identical event_id/content is a no-op; reusing it with conflicting content fails. A missing terminal event remains open, even after a crash.

If persistence fails before dispatch, hold dispatch and repair/reconcile the record. If it fails after dispatch or an external effect, preserve observed outcome and event identity in the invoking session's durable handoff, reconcile actual host/effect state, then retry only the recording; never redispatch the agent or repeat the external operation just to repair telemetry. Reject malformed/truncated ledgers unchanged; report recovery for explicit reconciliation without automatic truncation, deletion or a replacement run. No event file is an authenticity/completeness guarantee.

## Isolated roles

An explicitly invoked factory role uses an existing applicable execution identity when present. Otherwise the invoking main session creates one minimal real run for the standalone assignment, without generating a full specification or fabricating a multi-agent lifecycle. Reuse it across follow-up prompts and retries of that assignment. Ordinary skill invocation and normal bounded edits that do not invoke a factory role remain outside this telemetry. If no recording owner/access exists, the role may do useful authorized work and return an event candidate with capture pending; never claim complete capture. Logging unavailable before orchestration-managed dispatch holds that dispatch as above.
