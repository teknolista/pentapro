- FQU-01: ports/reproductions inventory behavior, tooling, development/installed/automated use, data, errors and presentation; preserve/adapt/exclude has rationale and affected criterion. Shared and per-platform requirements retain identity. No silent scope loss.
- FQU-02: a proportional criterion-to-evidence mapping lives in existing PROOF; source, rendered, task, human acceptance and execution origins remain distinct. Early vertical acceptance precedes expansion.
- FQU-03: factory repair continues in its authorized phase; only actual blockers stop dependent work. Compact packets preserve scope, evidence, environment, criteria, useful skill contribution and unknown outcomes.
- FQU-04: replace ui-design with standalone ui-design-web, ui-design-android and ui-design-terminal; web tools stay web, native procedures stay Android, terminal has viewport/resize/keyboard/progress/error and rendered checks. Mixed tasks can select multiple owners; retired skill has no forwarding alias.
- FQU-05: supporting command evidence records real exit status/time/snapshot safely; prior gates can be reused only with original receipt and justified affected-scope review. Behavior-changing negative controls cannot inherit unrelated green results.
- FQU-06: setup/update guidance and meaningful tests preserve permanent sections, adjacent text, provenance, local reversions, customizations, histories, index and idempotence. No automatic consumer updates.
- FQU-07: consequential decisions compare maintenance/proof costs and remain discoverable; routine work avoids extra ceremonies, agents or approvals. Metrics are optional, attributed and unknown where unavailable.
- FQU-08: catalog, generated metadata, README, active references, all-host role bodies, test inventory and migration guidance agree; historical reports retain recorded names and evidence. Offline, model and native-host claims are labeled separately.
- FQU-09: an isolated representative pilot exercises outcomes and negative controls; no unsupported percentage savings, universal readiness or fabricated TDD claims.

Every P01–P13 proposal is mapped to these capabilities in the implementation assessment; consolidated or already-supported items retain explicit dispositions.
