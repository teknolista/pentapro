# Coordinate a software factory run

Deliver the user's requested outcome, not merely a plan. Apply project instructions and use existing specialist skills as owners; this skill coordinates their handoffs and does not replace them. When project-local factory roles are available, use the applicable `factory_spec`, `factory_implementer`, `factory_verifier`, `factory_reviewer` and `factory_retrospective` roles for delegated work; the main agent orchestrates and integrates. Check actual host availability and policy. Maintain a compact run ledger and continue between completed stages without asking again for authority already granted. Read [the execution contract](references/execution.md), [role packets](references/roles.md), and [retrospective protocol](references/retrospective.md).

1. **Intake and baseline.** Identify repository, current work, request, target, branch and project policies, applicable skills, and separately authorized operations. Preserve existing work. Check only relevant safe prerequisites and baseline checks; record failures and unavailable targets. Choose a proportionate path: Record inapplicable optional stages with their reasons. Keep required gates pending until satisfied or lawfully waived under the project policy. Record unavailable verification explicitly.
2. **Specify and review.** For an OpenSpec request use the applicable explore/propose or apply skill; use PentaPRO when the project requires it. Review scope, canonical rules, risks, observable acceptance criteria, negative cases and feasible checks. Resolve routine choices; escalate only consequential ambiguity. A requested specification-only task stops there; an implementation request authorizes the necessary specification work and subsequent implementation.
3. **Plan and implement.** Split into small verifiable vertical slices with dependencies, paths, acceptance checks and evidence. Delegate independent tasks with disjoint write ownership when available. Execute the authorized work rather than stopping after investigation. Apply domain skills and project instructions; reconcile material contract conflicts before dependent edits.
4. **Verify and independently review.** Run appropriate checks on the integrated snapshot, exercise relevant real entry points, and map criteria to results or explicit gaps. Request a fresh read-only reviewer when available and authorized. Treat review as a separate judgment, not a test result. Substantiate findings, implement authorized fixes, rerun affected checks and re-review the changed snapshot. Keep retries bounded; report specific unresolved blockers. A self-review is not independent.
5. **Reconcile and deliver.** Update affected canonical specifications, tasks, documentation and evidence; verify final snapshot and rerun checks affected by reconciliation. Use git-ship or the applicable Git skill for explicitly authorized commit, push or PR. Verify actual published revision and CI where available. Merge, release, deploy and OpenSpec archive each require applicable authority. If archive follows publication, account for archive changes: validate and publish the resulting archive revision if authorized; otherwise report it as local pending publication. Never report the earlier revision as containing the archive.
6. **Retrospect.** After the requested terminal stages, independently assess the run using the retrospective protocol. If a requested stage cannot be completed, capture a provisional retrospective with that gap and resume when resolved. Propose improvements with evidence and expected effect; do not silently alter reusable skills or claim measured savings without a comparison.

Record a durable run ledger when project policy permits; otherwise provide a compact handoff in the conversation. Never put secrets or raw personal information in run records. Respect user permissions, sandbox and host restrictions; instructions and delegated packets do not grant tool permissions. If delegation is unavailable, do the available work directly, disclose lost independence, and leave any mandatory independent-review gate incomplete.
