# Adopt the native change lifecycle

This is a deliberate major process update, not an automatic conversion or a global installation. New work uses the PentaPRO six-file change contract and the host main session as exploration/orchestration agent. Keep the configured models, required permissions, project tools and meaningful checks.

## Existing projects

Inventory the accepted specification, active plans, historical changes, links, host profiles, installed skill sources, local edits and staged selections. Preserve them before reconciling current instructions. Do not replace customized project guidance with a blank template or relabel prior results as current evidence.

Map each active change explicitly to a unique native identity. Preserve baseline/source revisions, requirement and scenario IDs, task status, acceptance scope and evidence provenance in change.md and its five dimension files. Record which artifact owns each fact during transition; no change may have two competing lifecycle owners. If a missing baseline or conflicting decision prevents a faithful mapping, stop dependent work and report the exact gap instead of inventing it.

Retain prior archives and reports as historical evidence, with dates and original conclusions. Do not mechanically rewrite past records to pretend that they used the current process. Preserve legal attribution. Current skills, configuration and adoption guides use the native contract; historical records are not executable instructions. Retired project-local planning scaffolds and installed workflow packages should be removed from active discovery only after checking their exact paths, preservation needs and customizations. Never uninstall user-wide tooling or delete records as a side effect of setup.

New names contain two or three lowercase hyphen-separated words. Preserve imported identifiers through explicit mappings if necessary rather than silently changing accepted requirement identity. Do not collide with active or archived identities. Terminal archives use the actual local archival date and keep completed/cancelled disposition separate.

## Acceptance and delivery

One explicit approval of the reviewed result covers consolidation, archive, commit and normal push by default. Present this scope before the gate and preserve narrower or separate-approval requests. Do not interpret approval of the new policy as approval of unfinished work. Adoption of a template does not authorize merging or deployment.

Exercise at least an initial project and an existing-project change, plus negative feedback, cancellation/partial effects, archive collision and interrupted consolidation. Compare saved files, preserved baseline content, links and actual effects. Parsing a template, counting files or passing collection tests does not establish all-host workflow reliability.

The existing initializer and record helper are optional local conveniences, not a required SDD command surface. No schema engine or replacement SDD CLI is introduced. Actual application tests and secure engineering controls continue to use the project's own tools.
