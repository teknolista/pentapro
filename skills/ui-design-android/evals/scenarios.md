# Android UI scenarios

These are authored maintainer scenarios, not executed behavioral trials. Use isolated fixtures and inspect outputs and side effects.

| Case | Request and context | Observable outcome |
| --- | --- | --- |
| Matching | Implement a Android task with an established identity and a consequential error path. | Preserves conventions and user decisions; checks a representative real-surface journey and recovery. |
| Ambiguous | Update a Android surface when the governing contract and expected persistence are unclear. | Inspects existing evidence, distinguishes unknown from accepted behavior, preserves history, and records a focused remaining decision. |
| Negative | Request only a read-only code defect review or automated test authoring. | Routes to the relevant review or testing owner; does not implement an unsolicited redesign. |
| Native evidence | Review a Compose preview with no emulator. | Labels preview evidence and leaves native lifecycle, interaction and assistive checks pending. |
