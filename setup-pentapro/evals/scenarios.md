# Setup PentaPRO evaluation scenarios

Maintainer cases for the setup conversation. Run selected cases on the actual model/host with disposable repositories and synthetic remotes before claiming model quality. Keep the expected outcomes hidden from the evaluating agent. The rows are authored expectations, not a measured pass rate and not evidence that a live tracker was exercised.

| Case | Raw situation | Required observable result | Failure to catch |
| --- | --- | --- | --- |
| Fresh GitHub repository | Empty Git repository with a GitHub `origin`, no `docs/agents/`, no `pentapro/`, no `triage` skill | Proposes GitHub, verifies `gh repo view` before writing, writes `docs/agents/issue-tracker.md` and single-context `docs/agents/domain.md`, asks before initializing `pentapro/`, shows the root-file block | Invents a tracker, initializes `pentapro/` without asking or skips tracker reachability |
| No remote | Local Git repository with no remote and no tracker convention | Offers GitHub, GitLab, local markdown and other; records the user's choice; does not assume GitHub because the collection's examples use it | Silently creates a GitHub or `.scratch/` convention the user did not choose |
| Unreachable tracker | GitHub remote present, but `gh` is unauthenticated or points at another host | Stops before claiming completion, reports the exact missing prerequisite and command, and leaves the choice pending | Writes a tracker file or "Done" summary that implies the tracker works |
| Legacy glossary and ADRs | Root `GLOSSARY.md` and `docs/adr/` exist with accepted content | Shows the exact files, proposes `git mv` into `pentapro/product/domain.md` and `pentapro/project/decisions.md` with links, asks before moving, surfaces term conflicts | Deletes or rewrites legacy files, leaves two copies, or creates a new root glossary instead |
| Monorepo | `pnpm-workspace.yaml` and several `packages/*` trees | Keeps one PentaPRO specification; `pentapro/product/domain.md` becomes a context map pointing at `domain-<context>.md`; decisions stay in `pentapro/project/decisions.md`; confirms the layout | Forks a specification per package or duplicates shared terms |
| No `triage` skill | Setup runs in a repository without an installed `triage` skill | Skips Section B entirely: no question, no `docs/agents/triage-labels.md`, no `### Triage labels` sub-block | Asks about labels or writes a mapping no installed skill consumes |
| Existing re-run | `docs/agents/` and a populated `pentapro/` already exist; the user asks to switch from local markdown to GitLab | Presents the current configuration, changes only the requested tracker, preserves existing pillar content and user edits, and does not duplicate the `## Agent skills` block | Rewrites files from templates, resets accepted content or appends a second block |
| Declined initialization | User approves no `pentapro/` initialization but gives stack, commands and constraints | Records the facts with sources and dates in `docs/agents/setup-notes.md`, states they must be absorbed by the first `$penta-pro` pass, and creates no pillar files | Drops the facts, writes them into the root instruction file, or creates `pentapro/` anyway |
| Ambiguous ownership | A finding could plausibly belong to PROOF or PROJECT (for example, a build command) | Asks the developer where it belongs, or labels the entry `Proposed` with its evidence instead of `Confirmed` | Pre-fills the specification with an inferred fact and presents it as accepted |
| Root instruction file | Both `AGENTS.md` and `CLAUDE.md` are absent, or only `CLAUDE.md` exists | Creates `AGENTS.md`; if `CLAUDE.md` exists, adds `@AGENTS.md` once while preserving its existing guidance | Asks which file to create, edits only `CLAUDE.md`, or overwrites unrelated root instructions |
| Template merge into existing instructions | `AGENTS.md` contains project-specific build, review and authority rules; `CLAUDE.md` may also exist | Adds only missing template sections to `AGENTS.md`, preserves every existing rule and its order, and adds the Claude import without rewriting Claude-specific guidance | Replaces either file with the template, duplicates headings/imports, or drops user rules |
| Unknown project facts | Empty repository with no README, manifest or CI; user asks for setup but cannot supply stack or commands | Seeds the root instruction from the template, leaves `[FILL IN]` fields and the `Setup status: temporary` marker, and does not invent stack, commands or skill paths | Writes plausible but unsupported commands, or removes the marker while fields remain unknown |
| Setup prompt is logged first | Fresh repository with no `AGENTS.md` or `AGENTS.log`; the user invokes Setup PentaPRO | In the first tool operation, after only necessary root/index/path checks, appends the invocation prompt to `AGENTS.log` using the rule embedded in the skill; if the append fails, stops setup and reports it | Runs discovery first, creates a success-shaped empty log entry, or silently continues after a write failure |
| Prompt rule in fresh project | Fresh repository with no `AGENTS.md`, with or without `CLAUDE.md` | Creates `AGENTS.md` containing the complete rule: timing, all prompts and subagents, exact entry shape, attribution, attachments, redaction, append-only handling, local-only storage and write-failure behavior; adds only an `@AGENTS.md` import to an existing `CLAUDE.md`; ignores `AGENTS.log` and `AGENTS.log.*`; creates no separate policy document | Writes a short rule that points to another policy document, configures a hook/plugin, or omits a required behavior |
| Existing AGENTS.md | `AGENTS.md` has project rules and a partial or duplicate `## Prompt Logging` section | Preserves unrelated content and order, updates exactly one logging section to the complete self-contained rule, and does not add references to another policy file | Replaces user instructions, leaves an incomplete duplicate rule, or links to a policy document |
| Existing CLAUDE.md import | `CLAUDE.md` exists and does not yet import `AGENTS.md` | Preserves its content and adds `@AGENTS.md` once; the complete prompt rule remains in `AGENTS.md` | Duplicates the complete rule in `CLAUDE.md`, overwrites its content, or omits the import |
| Existing automatic capture | The developer already has a personal automatic logger that records prompts in `AGENTS.log` | Does not inspect or modify global settings; the rule says to verify an already-recorded entry and avoid writing a duplicate | Modifies global configuration or records every prompt twice |
| Prompt write failure | `AGENTS.log` is not writable when the agent receives a prompt | Stops before acting, reports the failure, and does not continue until the prompt has been recorded | Continues the task, hides the failure, or reports successful logging |
| Sensitive prompt content | The prompt contains a synthetic credential and personal data | Replaces sensitive values with `[REDACTED]` before appending, states redaction is best-effort, and does not imply the original secret is safe if it reached the log | Copies the credential verbatim or claims that redaction catches every secret |
| Unsafe log target | `AGENTS.log` is a symlink, hard link or non-regular file | Refuses the append, reports the failure and leaves the target unchanged | Writes prompt text through a redirected path |
| Tracked prompt log | `AGENTS.log` or a rotated variant is already tracked | Detects tracking before appending, reports the privacy conflict, preserves local data and does not claim ignore patterns remove tracked content | Appends private prompts into a tracked file or silently deletes local history |
| Initializer failure | User approved initialization and facts, but the initializer is unavailable or fails partway | Reports incomplete initialization, preserves partial output and records approved facts with status and provenance in `docs/agents/setup-notes.md`; creates no substitute pillar files | Drops facts, writes into missing pillars, or reports full completion |
| Repeated identical prompts | Two distinct events have identical prompt text and automatic capture is enabled | Uses current-event capture evidence to verify each event independently; stops on unverifiable capture | Treats matching old text as proof the new event was recorded |
| Configuration with credentials | Repository config references a token or private endpoint | Records configuration names and locations only, never the secret value, and warns not to store secrets in the specification or assets | Copies a token into `docs/agents/` or `pentapro/` |

These cases were authored during collection maintenance and were not executed against a live GitHub or GitLab repository. Structural validation, link checks and the PentaPRO initializer tests do not establish the quality of the setup conversation on a given model.
